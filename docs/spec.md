# Portwhisk V1 规格

状态：0.1.0 产品规格；安装与使用说明见 [项目说明](../README.md)。

本规格描述当前产品范围、实现约束和验收边界；工程过程与发布记录集中在模块文档，不作为功能规格内容。

## Problem Statement

用户希望从 Tinycast 快速选择一台 SSH 服务器，使用已经保存的用户名和密码完成登录，并在自己选择的终端工具中继续交互。

目前调查过的常见 SSH 扩展可以管理主机并启动终端，但没有同时提供所需的密码自动认证；接近需求的独立 SSH 管理应用又增加了单独安装和运行一套工具的负担。用户倾向于实现自己的扩展，名称统一为 Portwhisk。

需要解决的完整操作路径是：一次保存连接和密码、设置偏好终端，之后打开 Tinycast、搜索连接、回车、完成必要的系统授权或首次主机确认，最后进入选定终端中的 SSH 会话。正常重复连接不再要求手动输入服务器密码。

## Solution

提供直接导入 Tinycast 使用的 SSH 扩展，在扩展内完成连接管理与终端设置；用户不需要另外安装常驻的 SSH 管理应用或服务。

V1 提供「连接服务器」和「管理连接」两个主要命令，以及扩展设置中的默认终端选择。连接列表展示名称和可辨识的目标信息，支持搜索；管理界面支持新增、编辑和删除连接。连接信息存于本地，密码存于 macOS 钥匙串，不在连接列表或日常命令中显示。

选中连接并执行后，扩展在选定终端中启动本次 SSH 会话，由系统 OpenSSH 完成协议处理，通过受控的凭据辅助流程满足密码认证。服务器首次出现或主机密钥变化时保留真实的身份校验，不以自动化为由绕过。

本规格不要求绝对零点击：首次主机指纹确认、macOS 钥匙串或自动化授权等必要交互可以存在，但必须清楚说明其用途。成功启动终端、通过认证和进入远端 shell 是不同阶段；扩展只能报告自己实际知道的阶段。

## User Stories

1. 作为 Tinycast 用户，我希望直接安装或导入 Portwhisk 扩展，以便继续使用现有启动器管理 SSH 入口。
2. 作为 Tinycast 用户，我希望不额外安装常驻的 SSH 管理应用或后台服务，以便保持工具链简单。
3. 作为有多台服务器的用户，我希望为连接设置容易辨认的名称，以便快速找到目标服务器。
4. 作为 SSH 用户，我希望填写域名或 IP 地址、用户名和端口，以便连接实际使用的服务器。
5. 作为 SSH 用户，我希望省略端口时采用 22，以便快速配置常见连接。
6. 作为密码认证用户，我希望保存服务器密码，以便重复连接时无需重新输入。
7. 作为安全敏感用户，我希望密码由 macOS 钥匙串保存，以便连接列表和普通配置文件不包含明文密码。
8. 作为用户，我希望新增连接时得到地址、用户名和端口的明确校验，以便在保存前修正输入错误。
9. 作为用户，我希望先保存暂时不可达的服务器，以便在网络条件满足后再连接。
10. 作为用户，我希望打开「连接服务器」后看到已保存连接，以便无需记忆完整 SSH 命令。
11. 作为用户，我希望按名称、主机地址或用户名搜索，以便快速定位连接。
12. 作为用户，我希望列表同时展示连接名称与目标信息，以便区分名称相似的服务器。
13. 作为首次使用的用户，我希望空列表提供创建连接的入口，以便知道下一步操作。
14. 作为键盘用户，我希望可以通过键盘选择并执行连接，以便延续启动器的快速操作方式。
15. 作为用户，我希望在设置中自行选择受支持的终端，以便在熟悉的工具中操作远端会话。
16. 作为用户，我希望终端设置持久保存，以便每次连接不必重复选择。
17. 作为用户，我希望可选终端与实际安装情况一致，以便不会选到无法使用的应用。
18. 作为用户，我希望终端启动后提供可交互的 SSH 会话，以便继续输入命令、使用全屏程序和正常退出。
19. 作为密码认证用户，我希望凭据流程等待 SSH 请求认证时才提供密码，以便不会因固定延时而把密码误输入 shell。
20. 作为用户，我希望第一次连接未知服务器时仍能核对主机指纹，以便确认目标身份。
21. 作为用户，我希望主机密钥变化时得到 OpenSSH 的明确拒绝或提示，以便不误连到身份异常的服务器。
22. 作为用户，我希望可以编辑已有连接的信息，以便调整地址、用户名或端口。
23. 作为用户，我希望编辑非密码字段时保留现有密码，以便不必重新输入未变化的凭据。
24. 作为用户，我希望可以显式替换密码，以便在服务器改密后继续连接。
25. 作为用户，我希望取消编辑时不改变已有连接和密码，以便安全退出未完成的操作。
26. 作为用户，我希望删除连接前看到目标名称并确认，以便避免误删。
27. 作为用户，我希望删除连接时同时处理对应凭据，以便不遗留无用的服务器密码。
28. 作为用户，我希望钥匙串保存、读取或删除失败时得到明确提示，以便知道数据是否实际发生变化。
29. 作为用户，我希望终端未安装、权限被拒绝或启动失败时看到可操作的错误，以便修复环境后重试。
30. 作为用户，我希望密码错误时停止自动尝试，以便避免不断重试导致账号锁定。
31. 作为用户，我希望网络失败或认证失败时保留已保存配置，以便修正问题后重新连接。
32. 作为用户，我希望重复触发正在启动的同一连接时不会意外打开多个会话，以便避免误操作。
33. 作为用户，我希望终端启动成功后仍由终端管理会话，以便关闭 Tinycast 不会意外中断 SSH。
34. 作为用户，我希望密码不出现在日志、命令历史、剪贴板和进程参数中，以便快速连接不增加凭据暴露。
35. 作为使用特殊字符密码的用户，我希望引号、空格、反斜杠和 Unicode 等内容按原值传递，以便不因命令拼接而登录失败或执行意外命令。
36. 作为用户，我希望扩展重新打开后仍保留连接和终端偏好，以便日常重复使用。

## Implementation Decisions

### 已确定的产品边界

- 以 Tinycast 扩展为交付目标，优先采用其兼容的 Raycast 扩展结构；兼容 Raycast 本体可以作为自然结果，不列为独立发布验收目标。
- 产品只负责本地连接管理、凭据存取与外部终端启动，交互式 SSH 会话使用系统 OpenSSH。
- README 提供英文与简体中文版本；命令内界面通过扩展语言偏好切换，默认英文。宿主启动器入口使用固定英文标题并提供中文搜索词，不依赖未提供的系统语言接口。
- 密码认证与用户可选择终端属于核心能力，不能以「手动粘贴密码」或「固定系统默认终端」替代。
- 所有连接操作由用户主动触发。保存、编辑、搜索连接不接触远端服务器，不主动探测在线状态。
- 不安装独立常驻应用、LaunchAgent 或后台服务。允许扩展随包携带完成系统能力所需的短时辅助程序；辅助程序不能独立演变成另一套连接管理产品。

### 实现约束

- 使用 TypeScript 与 Raycast 扩展组件实现列表、表单和操作入口，由 Tinycast 渲染。系统能力通过 macOS 自带命令及 JavaScript 脚本调用，不引入 Swift 编译或自编译辅助二进制。
- 保持三处必要职责：连接数据与命令流程、凭据访问、终端会话启动。先用项目内模块组织，不拆成多个包、服务或通用适配框架。
- 「连接服务器」支持搜索和执行；「管理连接」负责增删改。两者可以共用连接读取和表单逻辑，不创建两套数据。
- 连接记录包含稳定 ID、名称、主机、用户名、端口和凭据引用。显示名称不充当主键；改名或修改主机不造成密码引用丢失。名称可重名，通过目标信息区分。
- 普通连接存储不包含密码。钥匙串条目使用扩展专属命名空间和稳定连接 ID 关联，避免同主机不同用户或重复连接互相覆盖。密码输入框使用安全输入组件，编辑时不回填已保存密码。
- 地址只接受主机名、IPv4 或 IPv6，不接受 SSH 命令或带用户名、端口的整段连接字符串；用户名非空，端口为 1 到 65535 的整数。名称、主机和用户名按各自语义处理空白；密码不 trim、不改写，拒绝不能被所选认证机制无损表达的输入并说明原因。
- 新增连接需要提供非空密码。编辑连接默认保留密码，只有用户选择「替换密码」并提交新值才更新；留空不能隐式清空旧凭据。V1 不提供单独移除密码后改为密钥模式的流程。
- 新增和修改必须在配置与钥匙串间维护一致性。任一步失败时保留原有可用状态，必要时执行补偿；补偿失败必须明确报告，不把部分保存显示为完整成功。
- 删除需要确认并同时处理连接与凭据。如果凭据无法删除，不将整个操作报告为成功；保留能定位和重试清理的数据，避免出现无法追踪的残留。
- 默认终端通过终端设置命令选择，支持 Terminal 和 iTerm2，只显示实际安装项；真实会话与系统授权的验收按终端分别记录。
- 每次连接创建新的可交互会话，优先使用新标签；所选终端只能可靠创建新窗口时允许使用新窗口。不得向用户已有的活跃会话盲目注入命令。V1 不提供窗口布局和标签/窗口偏好选项。
- 保存的终端不存在、无法唤起或不受支持时明确失败，不静默换到其他终端。应用识别和参数传递使用稳定标识及各终端已核实的启动能力，不承诺任意应用均可执行 SSH。
- 密码认证优先验证 SSH_ASKPASS 路线：即使 SSH 运行在真实终端中，也能在需要时通过受控辅助流程读取指定连接的密码。其在目标 macOS、系统 OpenSSH 与 Tinycast 中的实际行为是实现前置验证项，不能仅凭 API 名称判断可用。
- 终端中执行的启动信息只包含受控程序入口和非秘密连接标识。主机、用户名、端口不能被解释为任意 shell 命令、额外 SSH 参数或选项注入；所有跨进程输入都要按实际调用边界校验和转义。
- 凭据辅助入口只能为当前明确选定的连接处理本次认证，不按模糊提示猜测密码，不自动填写其他主机、sudo、跳板机或第二因素。密码不得通过命令行参数、全局环境变量、明文临时文件、终端输入模拟或剪贴板传递。
- 认证使用系统钥匙串。触发系统授权时保留其交互，拒绝或取消后停止；不得将失败掩盖成空密码或改用明文存储。
- 保留 OpenSSH 主机密钥校验，不自动接受未知指纹，不删除已知主机记录，不关闭严格检查以制造连接成功。使用已有系统 SSH 配置时也不能隐式关闭这些校验；检测到不满足身份校验约束的有效设置时阻止自动提供密码并说明原因。
- 一次连接只自动提供一次所存密码；拒绝认证后停止自动提供，不循环重试。服务器若需要额外认证，留给真实终端交互，并明确其不属于已完成的自动密码登录。
- 启动过程中对同一连接抑制重复触发，成功交接或启动失败后解除；不为已建立的 SSH 会话额外维护全局会话管理器。临时凭据通道和启动辅助资源必须有明确生命周期，失败或取消后完成清理。
- 扩展可以报告「已交给终端启动」或启动失败。没有可靠会话握手证据时，不报告「已登录」。交接后的网络、认证和 shell 输出由外部终端呈现；扩展不伪造持续监控能力。
- 没有现存用户数据需要迁移；不自动导入其他工具、既有 SSH 配置或历史实验文件。

## Testing Decisions

用户已确认：**以扩展命令入口的外部行为作为主要自动验证边界，真实 Tinycast、外部终端和 SSH 登录单列为后续联调验收。**

### 自动验证边界

- 优先通过执行命令、提交表单或操作入口验证结果：可见列表、保存结果、凭据引用、交给终端的目标以及用户收到的错误。测试不绑定内部函数调用顺序、组件层级或辅助文件命名。
- 在系统边界替换钥匙串与终端启动，使用无秘密的测试数据观察效果。命令流程仍运行真实的校验、状态转换和数据组合；不能在每层都 mock 掉后再宣称整体行为通过。
- 只有命令入口难以覆盖且涉及安全的部分增加小范围边界测试，例如参数转义、凭据通道输入校验；不为每个简单代理方法新增测试。
- 使用 Node 内置测试、React DOM 与受控系统边界检查，不新增整套测试框架；具体命令和检查层次见开发文档。

### 必须覆盖的行为

| 场景 | 可观察验收结果 |
| --- | --- |
| 首次使用、无连接、无搜索结果 | 显示正确空态，创建入口可达 |
| 新增、搜索、修改并重新打开扩展 | 普通字段持久保存，名称/主机/用户名可检索，密码不进入普通存储 |
| 非法主机、选项注入、非法端口、空用户名 | 保存被拒绝，错误指出问题字段，不执行远端连接 |
| 特殊字符、Unicode 密码和输入边界 | 密码按原值到达认证边界，不参与 shell 解释；不可表达内容明确拒绝 |
| 编辑保留密码、替换密码、取消表单 | 只发生用户明确提交的变化，原连接不会意外失效 |
| 配置写入或钥匙串写入失败 | 不报告完整成功，不丢失旧数据，残留可追踪 |
| 删除取消、正常删除、凭据删除失败 | 取消无副作用；成功同时处理配置与凭据；失败不隐瞒残留 |
| 切换终端、终端未安装、启动拒绝 | 启动目标遵循设置；失败有上下文，不静默换终端 |
| 连续重复触发与解除启动状态 | 启动期间不会重复建会话；结束后可再次主动连接 |
| 密码错误、钥匙串拒绝、额外认证 | 不无限重试，不清空凭据，不错误报告已登录 |
| 安全日志与错误输出 | 不包含密码、完整凭据或包含秘密的命令 |
| 辅助程序失败和取消 | 本次临时通道与资源按约定清理，既有终端会话不受影响 |

### 后续真实联调与完成门槛

- 在真实 Tinycast 中导入构建产物，验证配置控件、列表、表单、持久化及钥匙串授权；扩展能在 Raycast 中运行不能代替这一证据。
- 对每个宣称支持的终端，分别验证未启动、已启动有现有会话、正常密码登录、交互命令、正常退出，以及关闭 Tinycast 后 SSH 会话继续运行。
- 使用用户明确授权的测试 SSH 主机验证首次指纹确认、已知主机、主机密钥变化、错误密码、拒绝连接、超时及取消授权。不得使用生产服务器代替未提供的测试环境。
- 对 SSH_ASKPASS 和钥匙串的真实联动保留独立证据，自动测试中替换过的系统边界必须在此补齐。实际系统组合不支持时，停止受影响认证方案并重新评审，不退回延时模拟输入密码。
- 运行前检查实际测试脚本及其调用链。编译、类型检查和针对性非写入检查按实现范围执行；真实应用自动化、截图、浏览器或 Electron 测试不因本规格而自动获得执行授权。
- **V1 功能完成**要求命令行为验证、真实 Tinycast 验证、所有已宣称终端的真实会话验证及密码安全验证均有通过证据。当前本地规格完成不等于软件验收完成。

## Out of Scope

- 独立 SSH 管理应用、常驻守护进程、自建 SSH 服务、云端账户、遥测和云同步。
- SFTP、SCP、文件管理、端口隧道、服务器监控、批量远程命令、自动更新服务器和会话录制。
- 密钥生成或上传、自动部署公钥、私钥管理、跳板机密码链、多因素自动填写、sudo 密码自动填写。
- SSH 配置自动导入导出、其他工具数据迁移、备份恢复和密码明文导出。
- 任意终端的通用兼容、Windows/Linux 支持、窗口布局、主题、复杂标签分组和面向未来的插件平台。
- 发布商店和自动更新不属于扩展功能；仓库提交与 GitHub Release 属于工程流程，须有用户操作授权。
- 在未指定 Issue tracker 的情况下对外创建 Issue 或应用 ready-for-agent 标签。

## Further Notes

### 已确认边界

- 使用 Tinycast，保存连接及 SSH 密码，在所选终端启动独立会话；不另装独立连接管理应用。
- 名称统一为 Portwhisk，不设中文别名。
- 自动检查以命令入口外部行为和受控系统边界为主，真实应用/钥匙串/TTY/SSH 需要独立环境证据与授权。

### 调查依据

- [Tinycast 项目说明](https://github.com/abue-ammar/tinycast)：扩展兼容方向和本地启动器定位。
- [Tinycast 扩展安装](https://tinycast.dev/docs/extensions/installing/)：预构建扩展、源码来源和本地文件夹导入方式。
- [Tinycast 扩展兼容范围](https://tinycast.dev/docs/extensions/compatibility/)：API 与运行时支持边界。
- [SSH Connection Manager 源码](https://github.com/raycast/extensions/tree/main/extensions/ssh-manager)：连接列表、表单和终端设置的现有参考，不作为密码自动认证能力的证据。
- [Hop 源码](https://github.com/raycast/extensions/tree/main/extensions/hop)：多终端启动的参考；其自定义终端模拟输入方式不直接作为 Portwhisk 的可靠性保证。

这些来源仅用于设计背景。本规格不继承外部项目的发布状态、安全结论或实测结果，后续实现需核查当时的实际版本和依赖类型。
