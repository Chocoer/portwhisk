# 连接管理

## 当前结论

- 连接服务器和管理连接共用列表、添加/编辑表单及删除确认。输入校验覆盖主机名、IPv4/IPv6、用户名、端口与密码可表达性；保存、编辑和搜索不连接服务器。
- 普通记录位于 supportPath/connections/records.json，只有 id、name、host、username、port、credentialRef、status 七个字段；credentialRef 等于稳定 UUID，不保存密码。
- 新增先保存 pending，再写入钥匙串，最后标记 ready。编辑默认保留密码且不读取原值；显式替换才更新钥匙串。删除先写 pending-delete，清凭据后移除普通记录。
- pending 可清理，pending-edit 必须显式替换密码修复或删除，pending-delete 可重试删除。失败不报告全部完成，未完成记录禁止连接。

## 调用与一致性

- 列表/表单 → src/connections/store.ts 校验与进程内串行队列 → src/system-helper.ts stdin 协议 → assets/system-core.js 事务 → assets/system.js 的文件和 Security 接口。
- 所有写入及供密目标核对共用持久文件锁；持锁重新读取并比较完整快照，过期表单不能覆盖其他命令的修改。
- 文件采用 Foundation 原子替换；密码替换前禁用记录，补偿时先确认目标已禁用，再恢复旧凭据与元数据。恢复无法确认时保留可追踪状态。
- 新增凭据前持锁确认 pending 仍存在，避免迟到写入产生孤儿凭据。删除按专属 UUID 处理，不按显示名或主机批量操作。
- 钥匙串 service 为 dev.portwhisk.ssh，account 为连接 UUID；新条目使用空受信应用列表，不默认信任共享脚本运行器。已有条目的访问控制不自动修改。

## 验证与边界

- 命令回归覆盖入口、预填、保留/替换密码、取消、删除确认、失败恢复、重复触发与 stale 快照；纯核心检查注入文件/凭据故障验证补偿。
- JXA 检查实际运行 Foundation/CF 对象与文件边界，仅在测试副本替换 SecItem 调用，不读写真实凭据。密码始终保留原始字节语义，Unicode 规范等价不代替精确身份。
- 文件和钥匙串不是同一原子事务，进程中断依靠停用状态与显式修复处理。SSH 供密关联约束见[SSH 与终端](ssh.md)。
